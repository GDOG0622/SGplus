# SGplus

SGplus 是一个 SillyTavern 第三方扩展，把三件事合到一起：

- **资源下拉框分组** —— 预设、格式模板、UI 主题（美化）、世界书的下拉框变成可搜索、可折叠、可手动整理的分组列表。来自 [SillyTavern-SmartGroups（嘎嘎资源分组）](https://github.com/puppyyoho/SillyTavern-SmartGroups)。
- **预设条目管理** —— Chat Completion 预设**内部**的 prompt 条目支持分组、折叠、整组静音、批量操作、拖拽排序，以及一个跨预设复用的**全局库**。
- **正则列表分组** —— 全局 / 角色 / 预设三种正则列表都支持分组、折叠、整组开关、排序和搜索。

后两项取自 [ST-BaiBai-Tools（柏宝箱）](https://github.com/baibai-git/ST-BaiBai-Tools)，用零构建原生 JS 重写，视觉上与嘎嘎资源分组统一。

三层刚好互补：一层管「有哪些预设」，一层管「预设里有哪些条目」，一层管「有哪些正则」。

SGplus 不改写你的预设、模板、主题或世界书文件。所有分组记录都保存在 SillyTavern 的 `extensionSettings` 里；关掉扩展后，原生界面会完整恢复。

## 功能

### 资源下拉框

- Chat Completion、Text Completion、KoboldAI、NovelAI 等生成预设
- Context、Instruct、System Prompt、Reasoning 等高级格式模板
- UI Theme（美化 / 主题）
- 世界书：全局启用多选和世界书编辑选择器共用一套分组
- 以后由 SillyTavern 或其他扩展注册的 `data-preset-manager-for` 预设选择器

选择器是动态发现的，所以切换 API、导入新预设或世界书、重命名或删除资源后都不用手动刷新。

- 一个通用分组引擎服务全部资源，自动识别版本号、A/B 版、测试版、括号标签、分隔符前缀和共同名称前缀
- 自动分组与手动安排分离：手动移动过的条目会被「固定」，再次智能整理不会覆盖
- 统一管理器：在不同预设、模板、主题和世界书之间用标签页切换
- 小窗快速搜索、折叠分组、移动端布局、键盘 `Esc` 关闭
- 分组配置支持 JSON 导入导出
- 自动迁移旧脚本 `preset-group-manager:state` 里的「预设分组 v1.5.5」记录
- 兼容 Tauri 桌面 WebView：检测到 Tauri 时会为叠加式标题栏预留顶部空间
- 不提供「删除预设」捷径，永久删除仍交给 SillyTavern 原生按钮，降低误删风险

### 预设条目（Chat Completion）

在 SillyTavern 自己的 Prompt Manager 列表里就地生效，条目行仍然是原生结构，所以宿主主题和其他扩展都不受影响。

一条条目行上只有三样东西：名称、一个「⋯」菜单、SillyTavern 原生的开关。**所有次级操作都收在「⋯」里**——移动到分组、上移下移、编辑、查看、复制、存入全局库、从预设移除。列表因此保持干净。

- **条目分组**：新建、重命名、删除、折叠、整块上移下移。删除分组只让条目回到「未分组」，不会删条目。
- **智能整理**：用资源分组那套名称推断引擎去猜条目分组，已经手动分过组的条目不会被打乱。
- **整组静音**：整个分组不参与生成，但**保留每一条自己的开关状态**。静音期间条目行会变暗并标注「静音」，恢复后原状态原样回来。主提示词（`main`）始终保留，避免其他扩展的相对插入失效。
- **快速开关**：点开关只更新当前行，Token 统计延后合并刷新，不会每次都重建整份列表。
- **条目搜索**：按名称过滤，搜索时自动展开全部分组；中文输入法组词期间不会抖动，光标位置会保留。
- **多选批量**：批量启用、停用、移动到分组（可现场新建分组）。SillyTavern 不允许开关的条目会被跳过并在提示里说明。
- **拖拽排序**：桌面端可拖动条目跨分组、拖动分组整块换位；触屏设备改用「⋯」菜单里的上移下移，避免和页面滚动打架。
- **拖拽锁定**：工具栏的锁按钮可以一键禁用全部拖拽，防误触。
- **编辑条目后自动保存预设**（默认关闭）：开启后，保存条目编辑会顺带触发一次 SillyTavern 原生的「更新预设」，连续编辑会合并成一次保存。顺带的好处是分组也会一并写进预设文件。

条目顺序的唯一真源始终是 SillyTavern 自己的 `prompt_order`：一个分组就是这个数组里连续的一段。所以就算以后卸载 SGplus，条目顺序照旧，只是没有分组了。

### 全局库

一个**跨预设**的 prompt 片段货架，解决常用片段要在多个预设之间反复复制粘贴的问题。它在条目列表下方，默认收起。

- 在任意条目的「⋯」菜单里选**存入全局库**，就把它的名称和正文攒进去。
- 点库条目的 `＋` 把它**插入当前预设**。插入时会新建一条全新的 prompt（自动避开重名、自动生成新 identifier、默认启用、`role` 为 `system`），**不是引用**，所以之后改预设里的条目不会反过来污染库。当前预设有分组时会问你放进哪个分组。
- 库内可建分组，条目可拖进分组，也支持重命名、编辑正文、删除。
- 支持整库 JSON 导入导出，导入是追加而不是覆盖，同名分组会自动合并。

和柏宝箱不同，SGplus 的全局库**不需要任何自建后端**，数据存在 SillyTavern 的 `extensionSettings` 里，所以换浏览器也在。

### 正则列表

在 SillyTavern 自己的正则面板里就地生效，覆盖**全局 / 角色 / 预设**三个列表，每个列表各自独立分组（角色按角色卡区分，预设按预设名区分）。

这一层是**叠加**而不是重写：正则行还是 SillyTavern 自己渲染的那一行，只是被搬进了分组容器。所以原生的启用/禁用、编辑、删除、导出、跨作用域移动、以及 **Bulk Edit 批量模式**全部照旧可用，其他读取 `.regex-script-label` 的扩展也不受影响。

- **分组**：新建、重命名、删除、折叠、整块上移下移。删除分组只让正则回到「未分组」。
- **智能整理**：同一套名称推断引擎，按正则名字猜分组。
- **整组开关**：一键停用或启用整组正则。SillyTavern 在生成时直接读每条正则的 `disabled`，没有绕过它的办法，所以这里是真的逐条改——组内每条的开关会跟着整组一起动。
- **搜索**：按名称过滤，只影响视图，不动数据。
- **移动到分组**：每行都有一个「移动到分组」下拉框，它被放进 SillyTavern 原生的「⋯」收纳里，展开行才会出现，不占地方。
- **拖拽**：桌面端可拖正则跨分组、拖分组整块换位；触屏改用「移动到分组」。

**注意**：接管期间 SillyTavern 原生的正则拖拽排序会被停用。这是必须的——它靠读容器的直接子元素来重建正则数组，而分组容器没有正则 id，留着它会把你的正则存成空数组。关闭接管后会自动恢复。

## 分组记录存在哪里

预设条目的分组会同时写两份：

1. **镜像**：`extensionSettings` 里的 `promptGroups[预设名]`，每次改动立即保存。这样即使你没点「更新预设」，切换预设或刷新页面也不会丢分组。
2. **随预设**：当前预设的 `extensions.sgplus.promptEntries`。你点 SillyTavern 的「更新预设」或导出预设时，分组会跟着预设文件走，可以分享给别人。

两份都存在时取更新时间更晚的那份。SGplus 自己**不会**偷偷保存你的预设文件——要落盘到预设，仍然由你点原生的「更新预设」。

首次加载时，SGplus 还会读取柏宝箱写在预设里的 `extensions.baibaiToolkit.presetPromptGroups` 以及更早的 `extensions.entryGrouping`，所以从柏宝箱迁过来不用重新分组。

正则分组和全局库只存在 `extensionSettings` 里（分别是 `regexGroups` 和 `promptLibrary`），SGplus **不会**把它们写进预设文件或角色卡。资源分组、条目分组、正则分组和全局库都会被扩展设置里的「导出分组」一起带走。

## 安装

### 从 GitHub 安装（推荐）

1. 打开 SillyTavern 的「扩展」面板。
2. 选择「安装扩展 / Install Extension」。
3. 粘贴仓库地址：

   ```text
   https://github.com/GDOG0622/SGplus
   ```

4. 安装完成后重载页面。

### 手动安装

1. 下载仓库 ZIP 并解压。
2. 把整个 `SGplus` 文件夹放到以下任一位置：
   - 当前用户：`SillyTavern/data/<你的用户>/extensions/`
   - 全局：`SillyTavern/public/scripts/extensions/third-party/`
3. 重载 SillyTavern 页面；如未出现，请执行一次强制刷新。
4. 在「扩展设置」中找到「SGplus」，或从扩展菜单打开管理器。

需要 SillyTavern `1.12.0` 或更新版本。

## 使用

### 资源下拉框

- 点击任一被接管的预设、模板、主题或世界书下拉框，按分组浏览或直接搜索。
- 世界书的全局启用入口支持多选，点击条目可启用或停用且不会关闭面板；编辑入口仍保持单选并打开对应世界书。
- 点击小窗右上角的齿轮进入完整管理器。
- 「智能整理」只重新安排自动条目；用每行右侧的下拉框手动移动后，该条目会固定。

### 预设条目

1. 把 API 切到 Chat Completion。
2. 打开「AI Response Configuration」面板，往下滚到 Prompts。
3. 列表顶部就是 SGplus 的工具栏：搜索、智能整理、新建分组、多选、拖拽锁。
4. 每行的次级操作都在「⋯」里。列表最下面是折叠着的全局库。

分组是按预设保存的，换预设会看到那个预设自己的分组。

### 正则列表

1. 打开「扩展」面板，展开 **Regex** 区块。
2. Global / Preset / Scoped 三个列表各自顶部都有 SGplus 的工具栏。
3. 行内的「移动到分组」在 SillyTavern 原生的「⋯」展开里。

## 从旧扩展迁移

- **嘎嘎资源分组**：SGplus 使用同一套设置键（`smart_resource_groups`）和同样的 `srg-` / `pgm-` 类名，所以已有的分组和自定义 CSS 都能直接用。两个扩展不要同时启用。
- **柏宝箱**：预设条目分组会被自动读取。柏宝箱的其他优化（长聊天渲染、CodeMirror 编辑器、自动备份等）不在 SGplus 范围内；如果你要继续用那些功能，请在柏宝箱设置里关掉「预设分组」和「正则快速操作」，避免两套 UI 同时接管同一个列表。柏宝箱的全局库存在它自己的后端里，SGplus 读不到，需要手工搬一次。
- **预设分组 v1.5.5（酒馆助手脚本）**：首次加载会自动迁移它的 localStorage 记录。迁移完请关掉旧脚本。

## 安全与兼容性

- 扩展完全在浏览器端运行，不请求外部网络，不读取 API Key。
- 资源选中操作仍通过原生 `<select>` 的 `change` 事件完成，SillyTavern 仍是数据与行为的唯一来源。
- 预设条目列表和正则列表接管失败时都会自动回退到 SillyTavern 原生列表并在控制台留下原因，不会让你面对一个空列表。
- 如果拿不到 SillyTavern 的 Prompt Manager 或正则引擎（例如宿主版本差异过大），对应功能会整体静默停用，其余部分不受影响。
- 如遇冲突，可在扩展设置里分别关闭「接管预设」「接管主题」「接管世界书」「接管预设条目列表」或「接管正则列表」；原生界面会立即恢复。

## 开发

跑测试：

```bash
npm test
```

在一个一次性的 SillyTavern 沙盒里试跑（会克隆 SillyTavern 到 `.sandbox/`，默认端口 `8719`）：

```bash
npm run sandbox          # 首次会自动克隆并安装依赖
npm run sandbox:reset    # 重置用户数据后再启动
```

代码结构（零构建，浏览器直接加载 ES 模块）：

```text
index.js            引导、设置面板、菜单入口
shared.js           公共状态与工具（设置、弹窗、IME 安全搜索、Tauri 适配）
grouping.js         名称分组推断引擎
blocks.js           公用区块模型：一个分组就是宿主数组里连续的一段
resources.js        资源下拉框接管：快速选择器与分组管理器
prompts/host.js     SillyTavern Prompt Manager 桥接与可撤销的 patch
prompts/state.js    条目分组的数据模型、双层持久化、兼容读取
prompts/library.js  全局库的数据模型与片段编辑器
prompts/list.js     条目列表渲染与全部交互
prompts/index.js    条目功能装配与预设生命周期接线
regex/host.js       SillyTavern 正则引擎桥接、作用域键、原生 sortable 开关
regex/state.js      正则分组的数据模型
regex/list.js       正则列表的分组叠加层
regex/index.js      正则功能装配与事件接线
```

`prompts/host.js` 和 `regex/host.js` 是唯一接触 SillyTavern 内部模块的地方，都用动态 `import()` 加多路径回退，任何一步失败都只会让对应功能停用，不会影响其余部分。
